Until this release, adopting my spec-driven development skills meant copying folders by hand and reading a series of posts that each described an older version. Version 0.2.0 fixes both problems, and it is the first release I would point a team at.

## What is new

- **A documentation site** at [georgeracu.com/sdd-skills](https://georgeracu.com/sdd-skills/), with a page for every skill generated from its `SKILL.md`, so the docs cannot drift from the skills. Each page links to the post behind the skill and to the worked example.
- **A Claude Code plugin**, so the skills install with two commands and keep the `sdd:` prefix.
- **`/sdd:setup`**, which copies the work-item scaffold into a project, records the build and test commands in `AGENTS.md` and reports which optional inputs the other skills will find.
- **One verdict model** across the five review skills, with a single `**Status:**` line and a status that follows the highest severity.

## Install

```
claude plugin marketplace add georgeracu/sdd-skills
claude plugin install sdd@georgeracu
```

Then run `/sdd:setup` once in your project. The [getting started guide](https://georgeracu.com/sdd-skills/getting-started/) also covers `npx skills add` and a manual copy.

## Upgrading from 0.1.x

This release has breaking changes, and the [changelog](https://georgeracu.com/sdd-skills/changelog/) marks each one. The two most likely to affect you are the scaffold, which moved into the setup skill, and the status lines: the design review now says APPROVED WITH ISSUES where it said APPROVED WITH MINOR ISSUES, and the QA review moved Draft, Active and Complete to a new `**Stage:**` line. Update anything that reads a `**Status:**` line before you upgrade.

The [roadmap](https://georgeracu.com/sdd-skills/roadmap/) lists what I am considering next, and the [repository](https://github.com/georgeracu/sdd-skills) takes issues.
